### `Prologue.md`（序章）

**用途：** 把「现在的 AI 到底是什么」写成自己的判断，对应课纲里的「AI 祛魅」。

**内容分四部分：**

1. **常见用途**  
   用自己的话定义 LLM：海量文本训练、几乎都是 Transformer、按上文预测下一个词。再按「日常生活用户 / 互联网企业用户」列工具表，说明聊天、写作、识图、客服、RAG、编程助手等，底层多半仍是语言模型，企业场景还要接检索、权限和业务系统。

2. **前沿尝试：实力还是噱头**  
   判断标准是：能否复现、能否进生产、会不会一本正经地错。  
   - 截图建模：2D 图生成 3D 草稿，观感对、公差和材质仍要人验。  
   - 世界模型：要能根据动作预测下一步，不是只会生成好看视频。文中用马里奥、倒车入库、Sora、机器人倒水区分「拍片」和「内部预演」。

3. **能力边界**  
   强项：出初稿、有上下文时的总结改写、按格式输出、当学习陪练。  
   弱项：事实会编、不担责、不懂合规红线、长步骤会顺着错、看不见真实世界里没写进文字的变化。

4. **对个人的影响**  
   主要缩短「不会 → 会」的路径；同时强调 AI 给的知识要自己验收。

### `AI-Development-and-Core-Concepts.md`（1.1）

**用途：** 破除「AI 是魔法」的说法，把核心名词和当前阶段说清楚。

**内容：**

- **深度学习 vs Transformer：** 深度学习是方法；CNN / RNN / Transformer 是其中的网络。Transformer 的核心是 self-attention。
- **弱 AI / 强 AI / AGI：** 现在（文档按 2026 年写）是很强的弱 AI，擅长语言一类任务，还不能在全新领域稳定自学、发现自己错了就停下来。
- **名词分层：** LLM 用 token 思考；Agent = 模型 + 循环 + 工具；Loop 是观察→决定→行动→再观察；MCP 是接外部工具的统一接口；Skills 是按需打开的说明书；Harness 是权限和审批，防止乱改文件。
- **实力来源：** 参数规模提供容量，涌现是规模上去后某些能力突然好用，多模态让模型不只处理文字。
- **能力基座：** 文本理解、生成、推理三条腿；理解错了，后面会跟着错。
- **行业地图（2026 年 9 月）：** 国际（Anthropic、OpenAI、Google、xAI）和国内（Kimi、通义、智谱、DeepSeek、豆包、文心）各一张印象表，不当排行榜真理。

### `从零理解 Transformer.md`（1.2）

**用途：** 用尽量少的术语，把大语言模型从文字到计算走一遍，读完应能向非技术人员讲清注意力在干什么。

**内容按数据流展开：**

1. **本质：** 预测下一个 token 的概率，不是判断真假。文中用「上海联泰第三季度战略会」举例：公文套话概率很高，会议可以根本没开过。
2. **RNN 的限制：** 从左到右排队记，长了会糊。
3. **Transformer：** 每个词直接问其他词「谁跟我有关」。
4. **Token 与词嵌入：** 文本切成编号碎片；编号对应一串有远近关系的数字。
5. **QKV 注意力：** 用「小明把苹果给了小红，因为她饿了」讲 Query / Key / Value，再拆点积、缩放、Softmax、加权混合 V。
6. **多头：** 并排几组 QKV，同时看指代、语法、语义等不同关系。
7. **前馈网络与残差：** 注意力是互相看，FFN 是各自消化；残差把本层改动加回输入，避免叠很多层后早期信息丢光。
8. **位置编码：** 注意力本身无顺序，「狗咬人」和「人咬狗」必须另加位置信息；对比绝对位置编号和 RoPE。
9. **Tensor Core：** 大矩阵被切成小块做乘加；第一代好画的规格是 4×4，为下面的 Python 脚本做铺垫。

### `single_head_attention.py`（1.2 实操）

**用途：** 不依赖 NumPy，用纯 Python 把公式  
`Attention(Q, K, V) = softmax(QK^T / √d_k) V`  
逐步打印出来，方便和笔记、手算对照。

**内容：** 三个 token（小明、小红、她），向量只有 2 维。脚本会依次打印：

1. 原始分数 `Q · K`
2. 除以 `√d_k` 之后的分数
3. Softmax 权重（每行加起来为 1）
4. 权重混合 V 后的输出

预期现象：「她」那一行对「小红」的权重最大，输出更靠近小红的 `V = [0, 1]`。

运行：在本目录执行 `python single_head_attention.py`（需要本机已安装 Python）。

### `tensor_core_4x4.py`（1.2 实操）

**用途：** 对照课纲里的 Tensor Core 4×4 涂色图。数字与图中 A、B、D 一致：先手算 `D[0][1]`，再跑脚本核对。

**内容：** 两个写死的 4×4 矩阵 A、B。函数 `matmul_4x4` 用三重循环做 `D = A × B`（每个格子：一行和一列四个位置对乘再相加）。主程序打印完整 D，并单独拆开 `D[0][1]` 的四个乘积。

这是教学用的小规模矩阵乘，不是去调用真正的 GPU Tensor Core。

运行：在本目录执行 `python tensor_core_4x4.py`。

### `算力硬件全景.md`（1.3）

**用途：** 按业务场景区分四种计算单元，避免只听供应商宣传。

**内容：**

| 芯片 | 笔记里的定位 |
| --- | --- |
| CPU | 核少但每个核强，负责决定下一步 |
| GPU | 核多、擅长整齐的矩阵乘加，训练和推理主力；显存重要 |
| NPU | 把神经网络常用运算焊进电路，端侧推理能效通常更好（苹果 ANE、高通 Hexagon、华为昇腾等） |
| DPU | 帮 CPU 卸网络、存储、加密、多租户隔离；模型不会因此更聪明，集群更容易喂饱和更安全 |

文中区分训练 / 推理、云侧推理 / 端侧推理，最后用算力密度、能效比、编程生态、部署成本做四维对比表。

### `Linux实操.md`（1.3 实操）

**用途：** 把「在服务器上认硬件」做成一次真实记录，对应课纲里的 `lspci` 和 `nvidia-smi`。

**内容：** 在一台 NVIDIA Tegra / Orin 设备上的观察，不是通用教程。

- **`lspci`：** 看到 PCIe 桥、Wi-Fi、NVMe 硬盘、有线网卡。结论：没有 DPU；集成 GPU 焊在 SoC 内部，不会出现在这份 PCIe 名单里。
- **`nvidia-smi`：** 能看到 Orin 集成 GPU；CPU 为 ARM；NPU / DLA 这两条命令看不到。

用来练习：同一种芯片，不同命令能看见的范围不一样。
