# 1.3 算力硬件全景：GPU / CPU / NPU / DPU

---

## 一、CPU（中央处理器）


| 项目  | 我的理解          |
| --- | ------------- |
| 是什么 | 中央处理器，机器的大脑   |
| 功能  | 负责做决定，下一步要干什么 |
| 特点  | 核少，每个核都很强     |


## 二、GPU（图形处理器）


| 项目  | 我的理解                  |
| --- | --------------------- |
| 是什么 | 图形处理器，大规模并行计算之王       |
| 功能  | 真正堆量的计算：矩阵乘加，训练和推理的主力 |
| 特点  | 核多，每个核很简单，爱做同一件事      |


PyTorch、vLLM、几乎所有训练框架，默认都先为它写。

显存也很重要。

## 三、NPU（神经网络处理器）

专业为神经网络计算定制的芯片，注意是一块专用电路。

NPU 被设计成几乎只会做神经网络常用的那几步：矩阵乘、卷积、量化后的 INT8 / INT4 乘加

###理解

把神经网络里那几道固定工序焊进电路之后，同样算一遍，花的时间和电都更少。

同样识别一张脸或跑一遍端侧小模型：


| **用谁算** | **大致结果**                      |
| ------- | ----------------------------- |
| CPU     | 能算，核少、不适合这种整齐的乘加，又慢又费电，风扇容易转  |
| GPU     | 算得动，但唤醒一整块并行计算单元，待机和峰值功耗都更高   |
| NPU     | 电路只为这几类运算供电，完成同样次数的乘加，焦耳数通常更低 |


能效比：每瓦特能做多少推理。


| **名字**                          | **在哪**         | **典型用途**            |
| ------------------------------- | -------------- | ------------------- |
| **苹果 ANE**（Apple Neural Engine） | iPhone / Mac 里 | 拍照降噪、语音、端侧小模型，几乎不发热 |
| **高通 Hexagon**                  | 安卓手机 SoC 里     | 类似：端侧推理、影像、语音       |
| **华为昇腾 Ascend**                 | 服务器 / 集群       | 中国市场里对标 GPU 做训练和推理  |


端侧推理：模型已经训练好，在手机、电脑等设备上，输入新的数据再用一次这个模型。

推理（inference） 是相对 训练（training） 来说的。

- 训练：用海量数据调模型，贵、慢、在数据中心完成。
- 推理：已经训好的模型，拿一条新输入算出结果。

**”端“**指靠近人的那一端：手机、电脑、耳机、车上的芯片、摄像头，而不是云厂商的 GPU 集群。


|         | **云侧推理**                   | **端侧推理**               |
| ------- | -------------------------- | ---------------------- |
| 模型在哪跑   | 远程服务器（H100 / B200 那类）      | 手机、PC、车上的 NPU / 小 GPU  |
| 数据要不要出门 | 要上传                        | 可以不离开设备                |
| 典型例子    | ChatGPT、Claude、公司内部大模型 API | 面容解锁、拍照降噪、键盘联想、部分本地小模型 |
| 图什么     | 模型可以很大、很强                  | 低延迟、省电、能离线、隐私更好        |




## 四、DPU（数据处理器）

理解为：帮CPU干杂活的后勤。

功能：

1. 网卡收发
  多 GPU 要一起训练时，它们得不停互传参数。这种传输很快、很密，像仓库里传送带一刻不停。  
  普通网卡会把每个包裹丢给 CPU：「你来拆、你来转发」。DPU 自己就会拆、会转，CPU 不用一包一包过手。
2. 虚拟化、多租户隔离
  云上常常一张机器租给好几家公司。要保证：A 公司看不到 B 公司的数据和网。  
  前这套「隔间、门锁」也是 CPU 在管。DPU 可以自己管隔间，CPU 轻松一点，隔离也更硬。
3. 存储、加密、防火墙
  硬盘、走存储协议、加密、拦可疑流量，全是重复、规矩固定的活。DPU 就是干这类活的。

- 没有 DPU，GPU 照样能算
- 有了 DPU，模型不会突然更聪明，只是这堆 GPU 更能被喂饱、机器更好租、也更安全。



## 五、对比矩阵


| **维度**   | **意思是**              | **CPU**     | **GPU**     | **NPU**               | **DPU**          |
| -------- | -------------------- | ----------- | ----------- | --------------------- | ---------------- |
| **算力密度** | 同样体积/功耗下，能堆多少有效计算    | 低（核少）       | 训练/推理最高     | 端侧很高，数据中心看具体芯片        | 不比这个，看网络带宽       |
| **能效比**  | 每瓦特能产出多少 token / 次推理 | 差           | 中等偏上，数据中心主力 | 端侧通常最好                | 省的是 CPU 的电和核     |
| **编程生态** | 人会不会写、框架支不支持、出问题有没有人 | 最好（什么语言都能跑） | CUDA 一家独大   | 碎片化，绑定厂商              | 偏基础设施，应用开发者很少直接写 |
| **部署成本** | 买/租、电、散热、人、被锁死的风险    | 便宜、到处都是     | 最贵，电和散热都贵   | 端侧几乎「已经在设备里」；昇腾要算软件迁移 | 集群和云场景才值得单独买     |
